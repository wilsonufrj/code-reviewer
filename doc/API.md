# API Documentation

The service exposes an OpenAPI 3 specification generated by Springdoc. Start PostgreSQL and the
application, then open [Swagger UI](http://localhost:8080/swagger-ui.html) to inspect schemas or use
**Try it out**. The raw specification is available as
[JSON](http://localhost:8080/v3/api-docs) or [YAML](http://localhost:8080/v3/api-docs.yaml).

Base URL: `http://localhost:8080`

## Review endpoints

### `POST /api/reviews`

Fetches a pull request from GitHub, analyzes its changed lines, persists the result, and optionally
posts the findings to GitHub. Returns `201 Created`.

```json
{
  "owner": "octocat",
  "repo": "hello-world",
  "pullRequestNumber": 42
}
```

The response contains the review ID, repository, pull-request number, commit SHA, status, creation
time, and findings. Invalid input returns `400`; a GitHub failure returns `502`.

### `GET /api/reviews/repositories/{owner}/{repo}`

Lists persisted reviews for a repository, newest first. Returns `200` with an empty array when no
reviews exist.

### `GET /api/reviews/repositories/{owner}/{repo}/pulls/{number}`

Returns the latest persisted review for one pull request. Returns `404` when none exists.

## Repository information endpoints

### `GET /api/repository-info/repositories/{owner}/{repo}`

Returns public GitHub repository metadata, including its owner, language, visibility, dates,
star/fork/issue counts, and up to 100 contributors. GitHub `404` responses remain `404`; other
upstream failures return `502`.

### `GET /api/repository-info/authors/{username}`

Returns a public GitHub user profile and up to 100 repositories owned by that user, ordered by the
most recently updated. Profile data includes biography, company, location, follower counts, and
account dates.

## Webhook endpoint

### `POST /webhook`

Receives GitHub webhook payloads. Set `Content-Type: application/json` and the
`X-GitHub-Event: pull_request` header.

```json
{
  "action": "opened",
  "repository": {"name": "hello-world", "owner": {"login": "octocat"}},
  "pull_request": {"number": 42}
}
```

Supported actions are `opened`, `synchronize`, and `reopened`. A processed event returns `202` with
the review result. Unsupported event types or actions return `200` with no body.

## Error format

Errors use RFC 7807 problem details (`application/problem+json`) with fields such as `type`,
`title`, `status`, `detail`, and `instance`. The API uses `400` for validation failures, `404` for
missing resources, `502` for GitHub API failures, and `500` for unexpected errors.
